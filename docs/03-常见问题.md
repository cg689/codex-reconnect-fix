# 03 · 常见问题与踩坑

## Q1. 跑完 `Fix` 还是重连，怎么办？

按这个顺序排：

1. **完全退出客户端再启动**。`respect_system_proxy` 只在构建 HTTP client 时读取一次，热重载无效。注意托盘图标 —— 关窗口不等于退出进程。
2. **重跑体检**：`.\Diagnose-CodexReconnect.ps1`，看 `[4]` 端口是否 listen、`[5]` 经代理请求是否通。
3. **确认改的是一份配置**。Codex 的 Home 由 `CODEX_HOME` 环境变量决定，默认 `%USERPROFILE%\.codex`。如果你的安装用了别的目录，脚本会改错地方 —— 用 `-CodexHome <路径>` 指过去。
4. 三条都 OK 还重连，问题在**代理链路本身**（节点失效 / 订阅过期 / 出站配置错），换节点试。

## Q2. 会影响历史会话吗？

只要**不改 `model_provider`**，就不会。

Codex 的历史会话**按 provider 分组存储**，会话列表按当前 provider 过滤。这就是社区方案（替换 provider）最坑的地方：改完之后旧会话在新 provider 下「看不见了」。

> 不是真的丢了。把 provider 改回去，会话就回来了。

本项目的脚本只动 `[features]` 里的一行，`model_provider` 一个字都不碰。另外 `Fix` 会在备份目录里留一份改动前的 `config.toml`，随时可比对。

如果你已经因为改 provider 丢过会话，那是另一个工具解决的问题（需要同步 rollout / SQLite / 项目元数据）。

## Q3. 桌面版和 CLI 有什么区别，为什么能用不同方案修？

| | CLI（`codex`） | 桌面版（`OpenAI.Codex` / ChatGPT 桌面版） |
| --- | --- | --- |
| 自定义 provider | 可用，社区方案就是这条路 | **禁用** —— 实测卡在启动界面 |
| 模型列表刷新 | 无此环节 | 有，provider 配错会卡死在这里 |
| `respect_system_proxy` | 可用 | 可用，且是推荐的唯一路径 |

所以：**CLI 用户**两条路都行；**桌面版用户**只用特性开关这条路。

## Q4. 一定要用 v2rayN 吗？

不。任何提供本地 HTTP 入站端口的代理客户端都可以：

```powershell
.\Fix-CodexReconnect.ps1 -Port 7890     # 例如 Clash 系的常见端口
```

不传 `-Port` 时，脚本按这个顺序收集线索，然后**取第一个真的在监听的**：

| 顺序 | 来源 |
| --- | --- |
| 1 | `-Port` 指定的 |
| 2 | 当前 Windows 系统代理设置里已写的端口 |
| 3 | 本机代理客户端配置文件里的入站端口（v2rayN / Clash / mihomo / sing-box / Xray 的 JSON 与 YAML 布局都认） |
| 4 | 常见代理端口里正在监听的那个（7890 / 7897 / 10808 / 10809 / 2080 / 8118 …） |
| 5 | 上面都没命中时退回一个猜测值，并在报告里**标明这是猜的** |
| 6 | 兜底 `10808` |

两条实作上的讲究：

- **优先取在监听的**。一个没人监听的端口拿来写进系统代理，只会把整机网络弄断，所以「死的候选」永远不会盖过「活的候选」。
- **报告里会打印来源**。这样「端口猜错了」不会被误报成「代理挂了」—— 前者提示你用 `-Port`，后者才提示你去查节点。

YAML 配置只认**顶格**的键。订阅文件和 Clash Verge 生成的配置里，每个代理节点都带一个 `port:`（是节点的远程端口，不是本地入站端口），不加以区分会把几十个无关端口吸进来。

## Q4b. 双击 `.cmd` 被拦了 / 提示「Windows 保护了你的电脑」

三层拦截，按顺序看：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 双击后窗口一闪而过 | 脚本本身报错 | 在命令行里跑一次 `.\scripts\Diagnose-CodexReconnect.ps1` 看具体错误 |
| 「Windows 已保护你的电脑」蓝色弹窗 | `.cmd` 带 Mark-of-the-Web | 点「更多信息」→「仍要运行」 |
| 「无法加载文件……未对文件进行数字签名」 | 执行策略拦下 `.ps1` | 用 `.cmd`（内置了绕过），或 `powershell -ExecutionPolicy Bypass -File <脚本>` |

第三条在**纯下载 ZIP 解压**的情况下几乎必然出现：策略是 `RemoteSigned` 时，本地脚本能跑，但带「来自 Internet」标记的脚本不行。`git clone` 拿到的文件没有这个标记，所以能直接跑 —— 这也是 README 里 clone 排在前面的一半原因。

## Q4c. `Fix` 报 REFUSED 是什么意思

意思是**它替你拦下了一次会把机器搞断网的操作**，并且**什么都没写**。

触发条件是：目标端口 `127.0.0.1:<n>` 没人监听。此时如果把 `ProxyEnable=1` + `ProxyServer=127.0.0.1:<n>` 写进注册表，整台机器的 HTTPS 请求都会失败 —— 比重连问题严重得多。

退出码 `4`，同时给四个出口：

```powershell
# 1. 先把代理客户端打开，再跑一次
.\Fix-CodexReconnect.ps1

# 2. 端口就是别的（最常见：Clash 用 7890 而不是 10808）
.\Fix-CodexReconnect.ps1 -Port 7890

# 3. 不碰系统代理，只写用户级环境变量
.\Fix-CodexReconnect.ps1 -SkipSystemProxy -SetEnvironmentVariables

# 4. 确信端口马上会起来，硬上
.\Fix-CodexReconnect.ps1 -Force
```

检查分两层，`-SkipProxyCheck` 只关第二层：

| 层 | 查什么 | 需要联网 | 谁能跳过 |
| --- | --- | --- | --- |
| 存活 | 本地有没有进程在监听该端口（读内核 TCP 表） | 否 | 只有 `-Force` |
| 链路 | 经该代理能否连通 chatgpt.com | 是 | `-SkipProxyCheck` |

还有一种拒绝情形：端口**在监听，但经它访问不通 chatgpt.com**。这说明代理链路本身是坏的，此时写进系统代理同样会连累正常上网，所以也拒绝。**注意这条只在要改系统代理时生效** —— 加了 `-SkipSystemProxy` 就只告警不拒绝。

机器还没联网、只想先把配置写好：`-SkipProxyCheck` 跳过**联网链路**探测，但**端口存活检查照跑**（它读本地内核 TCP 表，不需要联网）——所以指向一个没人监听的端口仍会被拒绝。真要连存活检查一起跳过，用 `-Force`。`-DryRun` 下同样会走一遍检查，并告诉你「真正执行会停在这里」。

## Q5. 什么时候用 `-SetEnvironmentVariables`？

三种场景：

1. 你的代理客户端**不允许**开系统代理（有些客户端只开 TUN）；
2. 系统代理**被别的软件反复抢占**（那就别在系统代理这条路上耗，改用环境变量直给）；
3. 你只想影响 Codex，不想动整机网络设置。

```powershell
.\Fix-CodexReconnect.ps1 -SetEnvironmentVariables -SkipSystemProxy
```

写的是**用户级** `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`。注意只对之后启动的进程生效，必须完全重启客户端。

## Q6. 启动日志的黄色 WARNING 是什么？

`respect_system_proxy` 在上游被标记为 `Stage::UnderDevelopment`，启用后启动时会提示这是试验特性。功能是好的，警告只是提示。

消除它 —— 注意 `suppress_unstable_features_warning` 是**顶层键**，不在 `[features]` 表里，而且 TOML 要求顶层键写在第一个表头之前：

```toml
suppress_unstable_features_warning = true

[features]
respect_system_proxy = true
```

按上游警告文案（`unstable_features_warning_event`）原文，它就是让你在配置文件里设这个键。

## Q7. 日志里插件目录的 WebSocket 报错要管吗？

不用。`ps` / `mcp` 插件目录同步走的是另一条 `wss` 通道，在代理环境下偶有报错属于已知现象，**不影响对话**。

顺带一提：后端对 WebSocket 也走同一套代理解析（源码里有专门的 `SecureWebSocket` 分支），所以修好代理之后这条通道通常也会一起好转。

## Q8. macOS / Linux 能用吗？

- **macOS**：原理完全一样，开关也是 `respect_system_proxy`，上游有对应的系统代理解析实现（`macos::resolve`）。但本仓库的脚本目前只写 Windows 注册表和 `%USERPROFILE%` 路径，macOS 需要手动改 `~/.codex/config.toml`。
- **Linux**：该特性主要面向 Windows / macOS，Linux 下直接用环境变量即可。

手动改配置时，只需要保证：

```toml
[features]
respect_system_proxy = true
```

## Q9. 脚本会不会偷改别的东西？

`Diagnose` 是**纯只读**，连备份都不建。

`Fix` 只写两处：

| 写入位置 | 内容 |
| --- | --- |
| `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` | `ProxyEnable`、`ProxyServer` 两个值 |
| `<CodexHome>\config.toml` | 仅 `[features]` 下的 `respect_system_proxy` 一行 |

以及备份目录 `<CodexHome>\reconnect-fix-backups\`。

不碰：`auth.json`、登录态、插件配置、`model_provider`、其他注册表项。不装常驻进程，不建计划任务。先跑 `-DryRun` 可以逐条看清打算做什么。

**改系统代理前有一道闸**：先确认目标端口在监听（用内核的 TCP 监听表读，不是逐个连接试探），再确认经它能连通 chatgpt.com。任何一条不过就什么都不写并退出码 `4`（见 Q4c）。原始值已存进备份目录的 `state.json`，`Rollback` 会原样写回 —— 包括把 `ProxyEnable` 恢复成 `0`。

诊断脚本对系统是「读多写无」，修复脚本对系统是「先验后写、写前备份、可一键撤回」。这也是它比一条手工命令更值得用的地方。

## Q10. 手改 `config.toml` 会把文件写坏吗？

这是最容易踩的坑，脚本专门处理了：

- **不引入 BOM**。PowerShell 5.1 的 `Set-Content -Encoding UTF8` 默认带 BOM，而 BOM 会让 Codex 的 TOML 解析失败、直接读不出配置。脚本用 `UTF8Encoding($false)` 显式写无 BOM。
- **保留原有换行符**。检测文件本来用 `LF` 还是 `CRLF`，按原样写回。
- **逐字节保留其余内容**。注释、空行、键顺序都不动，只在 `[features]` 里加/改一行。
- **写入前先备份**。

自己手改的话，用 VS Code 之类的编辑器，注意右下角编码选 `UTF-8`（不是 `UTF-8 with BOM`）。

## Q11. 系统代理被别的软件抢来抢去

典型组合：主用 v2rayN，偶尔开某机场自家客户端。后者启动时把系统代理改指自己，退出时又把开关关掉、端口字段留残值 —— 表现就是「代理明明开着却断网」，叠加本问题就更难判。

这种场景二选一：

- **用环境变量**（`-SetEnvironmentVariables`），绕开系统代理这块是非之地；
- **上守护**：[v2rayn-proxy-guard](https://github.com/cg689/v2rayn-proxy-guard)，自动探测 v2rayN 端口并在系统代理被改写/关闭时夺回。

## Q12. 怎么确认修好了？

新建对话发一条消息，秒回且**没有** `Reconnecting 1/5` 提示，就是好了。

想更严谨，改动前后各跑一次 `Diagnose` 并对比：`-ReportPath before.txt` / `-ReportPath after.txt`。判据是 `[3] respect_system_proxy` 从 `FAIL` 变成 `OK`，末尾 VERDICT 从 `ROOT CAUSE FOUND` 变成 `OK - configuration is consistent`。

## Q13. 怎么彻底卸载？

```powershell
.\Rollback-CodexReconnect.ps1     # 还原 config.toml + 系统代理（会自动选最近一次备份）
```

然后把本仓库目录删掉即可。备份目录 `<CodexHome>\reconnect-fix-backups\` 可以留着，也可以删 —— 里面只有历史 `config.toml` 和一个记录代理状态的小 `state.json`。
